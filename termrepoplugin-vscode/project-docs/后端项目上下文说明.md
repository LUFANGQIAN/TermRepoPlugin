# 后端项目上下文说明

## 一、文档目的

本文档用于给一个全新的聊天会话、全新的后端项目，或新的协作者快速补充上下文。

目标是让对方在不了解当前插件实现细节的前提下，也能快速理解：

- 这个项目是什么
- 解决什么问题
- 当前插件已经具备哪些功能
- 当前产品气质与设计原则是什么
- 后端未来需要承接哪些能力

这份文档偏“高密度概览”，适合作为新会话的起始背景材料。

## 二、项目名称

项目名：`TermRepoPlugin-VSCode`

它是一个 VS Code 扩展，核心定位是：

> 面向开发者的术语积累、理解、管理与复用工具。

## 三、项目在解决什么问题

开发者在阅读代码、写命名、理解业务时，经常会遇到大量值得沉淀的技术术语、组合词和标识符，例如：

- `indexRouter`
- `retryPolicy`
- `userSessionStore`
- `authGuard`

这些词通常具有以下特点：

- 不是单纯英语单词，而是代码语境下的组合标识符
- 很值得长期积累，但手动整理成本高
- 下次命名时往往又想不起来自己之前是怎么表达的
- 非英语母语开发者尤其容易在“记住”和“复用”之间反复中断

该项目希望解决的是：

- 把代码中的术语和标识符沉淀为可复用的个人词库
- 帮助用户理解组合词/标识符的语义
- 让用户在以后写代码时，能快速把这些表达再拿回来使用

## 四、当前产品的核心理念

这个项目当前最重要的产品气质是：

- 本地优先
- 轻量
- 即装即用
- 工具感强
- 不强调重登录
- 不强调强商业化
- 对开发者友好

这是非常关键的背景。

未来即使接入云服务、AI 分析、云同步，也不希望破坏这几个特征。

## 五、当前插件已经实现的功能

截至当前版本，插件已经具备一个比较完整的本地词库闭环。

### 1. 收藏单词

用户可以：

- 在编辑器中选中一个标识符后直接收藏
- 无选区时手动输入单词
- 自动记录来源文件相对路径
- 自动拆分 `camelCase` / `snake_case` 标识符
- 为整体单词填写备注
- 为拆分片段填写备注
- 自动生成基础标签

### 2. 本地词库管理

插件提供了侧边栏 Webview 词库管理界面，支持：

- 搜索词条
- 新增词条
- 编辑词条
- 删除词条
- 复制词条
- 进入二级页面查看和编辑

### 3. 编辑器内复用

插件支持通过固定触发符快速搜索本地词库并插入单词。

示例：

```txt
%router
```

当触发符为 `%` 时，用户输入后即可从词库中搜索相关词条，并在补全面板中选中后插入目标单词。

搜索范围目前覆盖：

- 单词本身
- 整体备注
- 标签
- 拆词备注

### 4. 导入与导出

插件已经支持：

- 导出本地词库为 JSON
- 从导出的 JSON 再次导入
- 导入时跳过重复词条

### 5. 配置项

当前插件至少开放了以下配置：

- `triggerSymbol`
- `favoriteKeybinding`

其中：

- 触发符用于词库搜索替换
- 收藏快捷键默认是 `Alt+Q`

### 6. 文档与统一导出入口

项目已经对源码结构做过基础整理：

- `src/index.ts` 被整理为统一公共导出入口
- 已补充较系统的 JSDoc
- 可生成 TypeDoc 文档

## 六、当前技术实现概况

当前插件是一个前端工具型 VS Code 扩展，主要由以下模块构成：

- `commands/`
- `providers/`
- `storage/`
- `types/`
- `utils/`
- `views/`
- `extension.ts`
- `index.ts`

### 1. 存储层

当前使用本地 JSON 文件存储词库数据。

核心存储信息包括：

- 原始单词
- 整体备注
- 来源文件路径
- 拆词片段与片段备注
- 标签
- 创建时间
- 更新时间
- 预留复习字段

### 2. 当前没有后端依赖

当前版本插件是完全本地优先的。

也就是说：

- 没有登录
- 没有云端依赖
- 没有在线同步
- 没有 AI 调用

当前后端项目应被理解为“下一阶段增强能力”的承接方，而不是现有插件的运行前提。

## 七、当前已识别出的产品扩展方向

项目后续已明确希望扩展以下能力：

### 1. AI 默认备注建议

收藏单词时，希望通过大模型自动分析：

- 组合词
- 标识符
- 代码上下文

并生成：

- 整体备注默认建议
- 拆词片段备注默认建议

用户只需确认或微调，而不再从零填写。

这是当前最优先的云增强方向。

### 2. 云同步

希望实现：

- 词库跨设备同步
- 后续网页端共享词库
- 后续移动端复习应用共享词库

### 3. 多端生态

未来不只会有 VS Code 插件，可能还会有：

- 网页端
- 移动端复习软件

因此后端未来不只是“插件 API”，而更像一个统一的词库与 AI 服务层。

## 八、后端项目需要理解的边界

一个新的后端项目在开始前，需要明确以下边界。

### 1. 后端不是当前插件的前提

插件的基础功能必须继续保持：

- 不联网也能用
- 不登录也能用
- 本地词库独立可用

后端应被设计成增强能力，而不是基础门槛。

### 2. 插件不希望变成重 SaaS

当前产品不希望演变成：

- 首页登录
- 强账号中心
- 强商业化导向

更理想的方向是：

- 插件继续轻量
- 云能力按需接入
- 尽量只通过 token 或服务配置接入

### 3. 本地优先原则不能被破坏

即使后续加入后端能力，也不应让以下基础能力失效：

- 本地收藏
- 本地搜索
- 本地管理
- 本地导入导出

## 九、已经确认的云服务与商业化思路

当前已经形成的倾向性共识包括：

### 1. 不优先做插件内重登录

不希望插件一打开就是登录流程。

### 2. 云能力作为增强项存在

后端未来主要承接：

- AI 默认备注建议
- 云同步
- Token / 权限校验
- 额度控制

### 3. 当前更偏向“赞助制内测”

不是立刻做正式云服务套餐，而更倾向于：

- 用户赞助支持项目开发
- 赞助者获得云同步 / AI 能力的内测资格
- 用有限额度控制成本

### 4. 长期可能走“官方托管 + 支持自建”

作者倾向于：

- 插件代码开源
- 后端代码也愿意开源
- 支持愿意折腾的用户自建
- 商业化主要服务“不想折腾但想直接用”的用户

## 十、后端项目最可能先做什么

如果现在要新开一个后端项目，最推荐优先聚焦的能力是：

### 第一优先级：AI 术语分析接口

用于收藏单词时生成默认建议。

输入可包括：

- `word`
- `languageId`
- `fileName`
- `fileExtension`
- `surroundingCode`
- `filePath`

输出希望包括：

- `overallNote`
- `parts`
- `part.text`
- `part.note`
- `part.tags`
- `confidence`

### 第二优先级：轻量 token 能力

用于：

- 标识是否有 AI 内测资格
- 控制额度
- 控制调用频率

### 第三优先级：云同步能力

在 AI 默认建议跑通以后，再继续建设同步。

## 十一、对新后端项目的建议理解方式

如果你现在正在新建后端项目，请把这个项目理解成：

> 一个服务于本地优先 VS Code 插件的增强型后端。  
> 它的任务不是接管插件，而是为插件补充 AI 术语分析、云同步和后续多端共享能力。

换句话说：

- 插件是前台高频工具
- 后端是增强层
- 后端不应反过来把插件变重

## 十二、建议新聊天/新项目优先知道的信息

如果需要极简版背景，只记住下面几点：

- 这是一个开发者术语词库插件，不是通用词典
- 当前核心能力已经本地跑通
- 已有收藏、拆词、管理、搜索替换、导入导出
- 未来最优先的云能力是“收藏时 AI 自动生成备注建议”
- 插件强调轻量、本地优先、不重登录
- 后端应作为增强项存在，而不是基础门槛
- 长期可能支持云同步、网页端、移动端、自建服务与官方托管并存

TermRepoPlugin-VSCode 是一个本地优先、轻量、面向开发者术语沉淀与复用的 VS Code 插件；当前本地能力已经形成闭环，后端未来主要服务于 AI 自动备注建议、云同步以及多端词库共享。
